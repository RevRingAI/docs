## October 8, 2026

### The agent speaks while a tool runs
Give a custom tool an `executionMessage` such as "Hang tight, I'm pulling up your order" and the agent says it while a slow webhook works, then answers from the real result. Fast responses get no line. In the dashboard, open the tool and fill in **Say While It Runs**. Agents imported from Retell AI and ElevenLabs keep their execution speech. [Guide](/platform/tools#saying-something-while-a-tool-runs)

### Call variables in tool requests, and saving response fields
Use `{{name}}` in a tool's URL path, query values and header values, and save fields of a tool's JSON response as call variables with `responseVariables` for the tools that run next. In the dashboard: **Save Response Fields as Variables**. [Guide](/platform/tools#call-variables-in-requests)

### Silent tools and retries
`speakAfterResult: false` makes a tool run without the agent commenting on its result. `maxRetries` (0 to 3) retries a lookup after a connection error or a 429, 502, 503 or 504 response, within the tool's time limit. [Guide](/platform/tools#tools-that-do-not-need-a-reply)

### Calls that never connect fail fast
An outbound call that cannot be picked up by an agent within seconds is retried automatically, and if it still cannot be placed it fails right away with `no_agent_available` instead of staying in progress for up to 30 minutes.

### Voicemail
A recognised voicemail keeps the outcome `VOICEMAIL_DETECTED` even when the mailbox hangs up before a message can be left, hang-ups after a message are faster, and call screening assistants are answered with one short line and held quietly until the person or the voicemail prompt.

## October 7, 2026

### Talk to the agent during a call
Send the agent an instruction while a call is live with `POST /v1/calls/{id}/instructions`: have it say something now (`"speak": true`) or shape its next reply. Instructions appear in the transcript, and the MCP server has a matching tool. [Guide](/platform/outbound#steer-or-end-a-call-in-progress)

### Timeout per tool
Set `timeoutSeconds` (1 to 120) on a custom tool to give a slow webhook more time; the default stays 8 seconds. [Guide](/platform/tools)

### Hand off to another agent
An agent can pass the caller to another agent on the same call, with its own prompt, tools and voice, using `handoffRoutes`. The caller never redials, and the other agent picks up with the whole conversation. Chat tests follow handoffs too. [Guide](/platform/tools#hand-off-to-another-agent)

### Turn call recording off
Set `recordingEnabled: false` on an agent (or turn off **Record calls** on its Advanced tab) and no audio is recorded for its calls; transcripts and analysis are kept as usual. [Guide](/platform/data-controls#turn-recording-off)

### Failed tool calls are marked
Tool calls in call transcripts carry `isError: true` when the tool failed or timed out, so your systems and [alerts](/platform/alerts) can tell them apart from normal results.

### Pronunciation
Tell an agent how to say names, brands and abbreviations with `pronunciations` (for example Nguyen said as "Win"). Only the voice changes; transcripts keep the word as written. Agents imported from ElevenLabs bring their pronunciation dictionaries' alias rules. [Guide](/platform/multilingual#pronunciation)

### Caller keypad input
Turn on `keypadInput` and digits the caller presses, such as a PIN or an account number, reach the agent as their answer, with an optional finish key, digit limit and pause. Agents imported from Retell AI keep it on. [Guide](/platform/tools#caller-keypad-input)

### The voice follows a multilingual caller
A multilingual agent with language presets now switches to a language's preset voice when the caller changes language mid-call, and back to its own voice for other languages. [Guide](/platform/multilingual#the-voice-follows-the-caller)

### MCP servers on agents
Give an agent the tools of up to 5 MCP servers, such as your CRM, helpdesk or internal systems, next to its custom tools. Add them on the agent's **Tools** tab (with **Test connection** to pick the tools it may use) or with `mcpServers` on the agent. Tools load when each call, chat or text starts and never delay the call. Agents imported from Retell AI or ElevenLabs bring their MCP servers. [Guide](/platform/tools#mcp-servers)

### Per-call content, your own data, and safe retries
`POST /v1/calls` now takes `firstMessage`, `promptAppend`, `maxDurationSeconds` and `voicemailMessage` for a single call, `metadata` (your own data, up to 16 KB, stored on the call and sent in its webhooks), an `Idempotency-Key` so a retried request never dials twice, and `honorDoNotCall` to refuse numbers on your do-not-call list. [Guide](/platform/outbound#per-call-content-and-your-own-data)

### Voicemail rate and call filters
The dashboard **Overview** shows your voicemail rate (answered outbound calls that reached a voicemail box), and `GET /v1/calls` and the CSV export filter by hang-up cause, for example `?hangupCause=VOICEMAIL_DETECTED`. [Guide](/platform/outbound#call-logs)

## October 6, 2026

### Live booking on your calendar
Connect Cal.com or GoHighLevel (beta) on the new **Integrations** page (or `POST /v1/integrations`), then turn on **Appointment booking** on an agent's Tools tab (or set `booking`). The agent gets `check_availability` and `book_appointment`: it offers only the times your calendar returns, confirms the one the caller picks, and books it live on calls and in chats. Calendar keys stay on our side and never reach the agent. [Guide](/platform/integrations)

### Contact memory
Agents can now remember the people they talk to. With `contactMemory` (or **Contact memory** on the agent's **Numbers** tab), each call adds what matters for next time to a short memory kept for the person's phone number: the name they go by, what they want, appointments with dates, concerns and next steps, never card numbers or IDs. The next call, inbound or outbound, starts with it. See, correct or erase memories with `/v1/contacts`. Off by default. [Guide](/platform/contact-memory)

### Callbacks, recognized
When someone you called in the last 30 days calls your agent's number back, the agent knows it is a callback: the outbound call's variables (their name, your lead ID) come with the call, the agent is told how that call went and what was said, and it greets a returning caller instead of repeating an opening written for calls it places. Callbacks carry `is_callback`, `callback_call_id`, `last_call_time` and `last_call_outcome`, and your pre-call webhook gets a `callback` object. On by default; tune it with `inboundCallbacks` (window and an optional callback greeting) or on the agent's **Numbers** tab. [Guide](/platform/inbound#callbacks)

### Do-not-call requests, handled automatically
Turn on `doNotCallDetection` (or **Detect do-not-call requests** on an agent's Advanced tab): when a caller asks not to be called again, the call shows `doNotCallRequested: true`, the post-call webhook carries it, and their number joins your do-not-call list so campaigns never dial it. Declining an offer or asking for a call back later does not count. [Guide](/platform/campaigns#add-callers-who-ask-automatically)

### A/B test agent versions
Split an inbound number's calls between versions of an agent with `trafficSplit` (2 to 5 environments with weights), then compare them with `GET /v1/analytics/versions`: failure rate, call length, negative sentiment and success-criteria pass rates per version. [Guide](/platform/versioning#split-calls-between-versions)

### Response latency on every call
Each call's `metrics.latency` now shows how quickly the agent answered: the caller's wait from the end of their speech to the agent's reply, broken into turn detection, transcription, thinking and voice, each as p50, p90 and max across the call's turns. [Guide](/platform/webhooks#response-latency)

### One agent, many languages
Pass `language` when you place a call (or from your pre-call webhook for inbound calls) to run that call in the caller's language, and give the agent `languagePresets`: a voice and opening line per language, used whenever a call runs in that language. Agents imported from ElevenLabs bring their per-language opening lines. [Guide](/platform/multilingual#one-agent-many-languages)

### Alerts
Hear about problems before your customers do. Create alerts on failed calls, calls failing a success criterion, negative caller sentiment, tool errors, undelivered post-call webhooks or call volume, for one agent or all, over 15 minutes to 24 hours. Each alert sends one webhook or Slack message when it fires and one when it resolves, with a test button and a history of every notification. Open **Alerts** in the dashboard or use `/v1/alert-rules`. [Guide](/platform/alerts)

### Knowledge from whole websites, kept current
A URL source can now read a whole help center or documentation site: add `crawl` with `maxPages` (up to 50) and an optional `includePath`, and RevRing follows the site's links under that path into one source. Set `refreshDays` to read the pages again on a schedule, or refresh a source on demand with `POST /v1/knowledge-bases/{id}/sources/{sourceId}/refresh`. Agents keep answering from the current content during a refresh, and new content replaces it only once it is fully indexed. [Guide](/platform/knowledge-bases#whole-websites)

### Caller sentiment, re-run analysis and call export
Every call with caller speech now carries `sentiment` (positive, neutral, negative or unknown) on the call and in the post-call webhook; Retell-format webhooks fill `user_sentiment` from it. After changing an agent's extraction fields or success criteria, re-run the analysis on past calls (`POST /v1/calls/{id}/reanalyze`, up to 50 at once with `POST /v1/calls/reanalyze`, or **Re-run analysis** on a call). Download call history as CSV with sentiment, variables, extracted data and evaluation results (`GET /v1/calls/export`, or **Export CSV** on Call Logs). [Guide](/platform/webhooks#caller-sentiment)

### Transfer events on your webhook
Add `transfer.started`, `transfer.bridged` and `transfer.cancelled` to an agent's `webhookEvents` (or turn on **Also send transfer events**) to hear about transfers as they happen: started (warm or cold, with the destination), connected, or not completed (declined, voicemail or failed). Agents using the Retell compatibility format receive Retell's `transfer_started`, `transfer_bridged` and `transfer_cancelled`. [Guide](/platform/webhooks#transfer-events)

### Listen to calls live
Open any call in progress in the dashboard and select **Listen** to hear both sides as it happens. Nobody on the call can hear you or knows you are listening, so the call is never affected. The transcript on the same page updates every few seconds while the call runs.

### Remove personal details from call transcripts
Set an agent's `storageMode` to `redact_pii` (or choose it under **Advanced > Call data storage**) and names, phone numbers, emails, addresses, dates of birth, ID, card, account and medical record numbers, and passwords are replaced with labels like `[phone_number]` in every call's transcript and summary, before the call is stored or sent to your webhook. Pick categories with `piiCategories`. Calls show `piiRedacted: true`. Agents imported from Retell AI or ElevenLabs carry their PII settings over. [Guide](/platform/data-controls)

## October 5, 2026

### Connect Twilio in one step
Bring Twilio numbers over with your Account SID and Auth Token: RevRing creates the Elastic SIP trunk, points it here, moves the numbers you pick and can assign them to an agent. From the dashboard (**SIP Trunks > Connect Twilio**) or `POST /v1/sip-trunks/connect/twilio`. [Guide](/platform/telephony#connect-twilio-in-one-step)

### Fix failing calls
Build a test suite from an agent's recent calls that failed a success criterion and run it, in one step from the dashboard Overview or `POST /v1/test-suites/from-failing-calls`. Success criteria now count a skipped required action as `fail`; an outcome the call never reached stays `unknown`. [Guide](/platform/test-suites#fix-failing-calls)

### Create a test from a real call
One click on a call (or `POST /v1/test-suites/{id}/tests/from-call`) turns it into a test case: the caller's side becomes the script, the failed success criteria the rubric. [Guide](/platform/test-suites#from-a-real-call)

### Call started event
Set `webhookEvents: ["call.started"]` on an agent to get a webhook when each call connects, in RevRing's shape or Retell's `call_started`. [Guide](/platform/webhooks#call-started-event)

### Route inbound calls from your pre-call webhook
The pre-call webhook's answer can now pick the agent or environment for the call, override the opening line, voice or prompt, or reject the call. Retell and ElevenLabs inbound webhook answers work unchanged. [Guide](/platform/webhooks#route-personalize-or-reject-the-call)

### Manage RevRing from Claude, Cursor and VS Code
A management MCP server at `https://api.revring.ai/v1/mcp` lets AI tools list and edit agents, place and end calls, and read transcripts and results with your API key. [Guide](/mcp-server)

### Keep your webhook handler when you switch
Set `postCallWebhookFormat` to `retell` or `elevenlabs` and the post-call webhook arrives in that platform's payload shape, filled from the RevRing call record. The importer sets it automatically. [Guide](/platform/webhooks#compatibility-formats)

### Knowledge bases hold 50 sources
The limit per knowledge base is now 50 sources (was 10).

### Campaigns
Call a contact list with one agent. Contacts without a time zone are called in the local time of their number's area code, and `voicemailStrategy: "last_attempt"` leaves a voicemail only on the final attempt. Calling windows follow each contact's own time zone, retries happen automatically by outcome (no answer, busy, voicemail, declined, failed), new calls are paced to suit your carrier, numbers on your do-not-call list are never dialed, and a CSV export carries every contact's outcome with extraction and evaluation columns. Campaign calls carry `campaignId` on the call record and in the post-call webhook. [Guide](/platform/campaigns)

### Import agents from Retell AI and ElevenLabs
Bring existing voice agents over with your API key for the other platform. A dry run reports how every setting carries over (prompt, opening, variables, tools, transfers, voicemail, knowledge, post-call analysis) and what is left to you; importing creates the agents with their tools and knowledge bases, and importing again updates them. [Guide](/platform/importing-agents)

### End a live call from your server
`POST /v1/calls/{id}/end` hangs up a call in progress immediately; it is recorded as `API_ENDED` and still gets its recording, summary and post-call webhook. Use it when your own logic decides the call should stop. [Reference](/api-reference/calls/end)

### Concurrency headroom
`GET /v1/analytics/active` now also returns `concurrency` (`active`, `limit`, `available`), counted exactly like the check behind `concurrency_limit`, so dialers can pace calls instead of retrying. [Reference](/api-reference/analytics/active)

### Spoken text never reads a placeholder aloud
If an opening line, voicemail message, hold or intro message references a `{{variable}}` that has no value on a call, the placeholder is dropped and the sentence tidied ("Hi {{first_name}}, this is Maya" becomes "Hi, this is Maya") instead of being read out.

### Webhook signing
Every webhook RevRing sends (pre-call, post-call, message received) can now be signed. Create a secret with `POST /v1/webhooks/signing-secret` and verify the `X-RevRing-Signature` header on the raw body. Opt-in per organization; nothing changes until you create a secret. [Guide](/platform/webhooks#verify-webhook-sources)

### Webhook retries
A post-call webhook that fails (connection error, timeout, non-2xx) is retried 1, 5 and 30 minutes later. Handlers should be idempotent on the call `id`. The outcome is on the call record as `postCallWebhookStatus` and `postCallWebhookAttempts`. [Guide](/platform/webhooks#response-expectations)

### Test runs against a live version
Test runs use the saved draft by default. Pass `environment` (`production` or an environment name) on `POST /test-suites/{id}/runs` to test the version callers get. [Guide](/platform/versioning#testing-before-you-publish)

## October 4, 2026

### Drafts, publishing and environments
Agents can now be edited without going live. Switch an agent to manual publishing (`publishMode: "manual"`), edit the draft, test it, and publish when ready; earlier versions can be made live in one call. Named environments pin a version with their own variable defaults and can be bound to inbound numbers, the web widget and `POST /calls`. Every call record carries the version it ran on. [Guide](/platform/versioning)

### Post-call data extraction
Define typed fields per agent (`postCallExtraction`) and get them filled from each conversation on the call record and in the post-call webhook as `extraction`. [Guide](/platform/webhooks#post-call-data-extraction)

### Post-call evaluation
Write success criteria per agent (`postCallEvaluation`) and every call is judged pass, fail or unknown with a one-sentence reason. Pass rates per criterion are on the analytics overview and the dashboard. [Guide](/platform/webhooks#post-call-evaluation)

### SIP trunk address validation
A trunk's proxy must now be a hostname or IP that resolves. Typos such as a misspelled carrier domain are refused when the trunk is created instead of producing a trunk that can never place a call. [Reference](/api-reference/sip-trunks/create)

### Noise suppression for every agent
Background noise and other voices on the caller's side are suppressed before the agent listens. On by default for all agents; turn it off per agent with `noiseCancellation: "off"`.
